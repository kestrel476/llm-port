# llmport

Контракт, адаптеры и поведения для подключения к языковым моделям.

Пакет собирается в трёх слоях с разной судьбой. Это ответ на вопрос, почему прошлая
попытка вынести общий код (`llmconnector` в lorium) не прижилась: её вынесли как пакет
**с реализацией**, реализация не подошла следующему сервису, её правили на месте — и
копии разошлись на сотни строк.

| слой | что внутри | как часто меняется |
|---|---|---|
| `contract` | сообщения, запрос, результат, протокол провайдера | почти никогда |
| `adapters` | специфика вендоров, независимы друг от друга | по мере надобности |
| `behaviours` | повторы, фолбэк, события — надстройки над контрактом | редко |

Сервис берёт то, что нужно ему. Не подошёл наш фолбэк — берёт адаптер и пишет свой,
контракт при этом не нарушен.

## Зависимостей нет

Ни одной, включая HTTP-клиент: пакет подключается в полтора десятка сервисов, у каждого
уже свой `httpx` или `aiohttp` своей версии. Транспорт передаётся функцией.

Для тех, кому свой клиент не нужен, в `llmport.transports` лежит реализация на
стандартной библиотеке. Она необязательна и ничего не навязывает, но во внутреннем
контуре снимает вопрос: каждое колесо туда приходится проносить отдельно и согласовывать.

## Два контура GigaChat

Снаружи ключ меняется на токен. Внутри токена нет вовсе: клиентский сертификат и ключ
предъявляются при установлении соединения, обменивать и обновлять нечего, а заголовок
`Authorization` эндпоинт не ждёт. Способ выбирается по тому, передан ли `tokens`.

```python
from llmport import build_ssl_context, urllib_transport
from llmport.adapters.gigachat import GigaChat, TokenCache

# внешний контур: ключ обменивается на токен
transport = urllib_transport(build_ssl_context(verify=False))
external = GigaChat(tokens=TokenCache(authorization_key=KEY, transport=transport), transport=transport)

# внутренний контур: авторизует рукопожатие
mtls = urllib_transport(build_ssl_context(client_cert="client.pem", client_key="client.key", verify=False))
internal = GigaChat(transport=mtls)
```

Адрес выбирается вместе со способом, поэтому задавать его отдельно не нужно. Помнить об
этом должен адаптер, а не каждый из сервисов.

Различий, из-за которых это не сводится к «не слать заголовок», три. Ошибка выглядит
иначе: не 401, а обрыв рукопожатия, и сообщение будет про TLS, а не про доступ, поэтому
и адаптер, и транспорт подставляют в него подсказку про сертификат. Логика обновления
токена не нужна, но код, который её ждёт, без неё падает. И на 401 повторять нечего:
обновлять нечего, отказ означает, что контур сертификат не принял.

Проверка сертификата сервера отключается осознанно (`verify=False`): своего
удостоверяющего центра в системном хранилище обычно нет, а соединение всё равно остаётся
взаимно аутентифицированным. Умолчание при этом строгое.

## Устойчивость

```python
from llmport.behaviours import AsyncResilient
from llmport.policy import RetryPolicy

llm = AsyncResilient([primary, spare], role="skill_agent", retry=RetryPolicy(attempts=3))
answer = await llm.complete(request)
```

Ключевое отличие от копий, живущих сейчас в трёх репозиториях: они перехватывают
**любое** исключение и уходят на запасную модель всегда. Здесь решение принимает
`policy`, и на постоянных ошибках фолбэка не происходит:

| ошибка | повтор | фолбэк |
|---|---|---|
| таймаут, обрыв, 5xx, 429 | да | да |
| неверный ключ (401/403) | нет | **нет** |
| запрос не принят (400) | нет | **нет** |
| нет такой модели (404) | нет | **нет** |
| ответ не разобран | да | да |

Почему так: если уйти на запасную модель при неверном ключе, сервис получит ответ и
продолжит работать. Поломанная конфигурация останется в проде незамеченной, а качество
тихо просядет — ровно этот сценарий объяснил «необъяснимые» 2% расхождений в замерах.

## Наблюдаемость

Библиотека не логирует и не пишет метрики — она сообщает события, а решает сервис:

```python
AsyncResilient(candidates, role="suggestions", listener=my_handler)
```

Самое важное событие — `FailedOver`: оно означает, что сервис работает **не на той
модели**, для которой его настраивали.

## Сборка запроса проверяется без сети

`build_payload` и `parse_response` — чистые функции. Это не эстетика: половина ошибок
в замерах жила именно в сборке запроса и обнаруживалась по странным цифрам после
двадцатиминутного прогона. Например, `reasoning` кладётся в корень запроса, а не в
`extra_body`: последнее — понятие SDK OpenAI, при прямом HTTP оно молча игнорируется.
